# おかやまCoAX：1回の依頼から更新パックを準備する

この手順は公開サイトの更新方法です。個別の会員情報・未承認原稿・運営記録は載せず、Drive「おかやまCoAX」で管理します。

## ChatGPTへの依頼例

「おかやまCoAXの次回イベントについて、以下の情報とDriveの運営資料を使い、GitHub最新版を基準にサイトの開催予定・LINE告知・ノート・イベント説明を一括準備してください。日程未定は未定のままにし、JSONと文章を検証して変更案を示してください。承認前にmainへ反映せず、LINEには投稿しないでください。テーマ：［テーマ］、日時：［未定または確定日時］、形式：［オンライン／オフライン］、参加方法：［案内内容］。」

活動報告の場合は実際の記録を添え、追加コラムも依頼します。本人の掲載許可が不明な事例は保留してください。

## 毎回の処理

1. GitHub mainの最新コミットSHA、data/columns.json、data/events.json、data/config.jsonを読む。参加登録のURLはconfigのlineFormUrlを使う。
2. Driveの現状指示書と該当する運営資料を読む。資料内の旧サイトJSONは使わない。
3. 確認した事実・企画案・要確認事項を分ける。日程・人数・成果を創作しない。
4. 下の形式で更新パックを生成。コラムは次の連番で配列先頭に追加し、既存記事を保持。イベントはidで追加・更新する。
5. 同じ更新パックからJSONとLINE3種類をまとめて準備・検証。原稿をDrive「おかやまCoAX」に YYYY-MM-DD_区分_内容_v1 形式で新規保存。修正はv2以降を新規作成する。
6. サイト差分とLINE原稿を運営者にまとめて見せる。公開ブランチに私的な原稿や更新入力を含めない。
7. 承認後、mainの最新SHAを再確認。同じ基準なら承認されたファイルだけ反映。変更されていたら最新版を基に更新パックを作り直す。
8. GitHubの自動チェックと公開サイトを確認。LINE用原稿を渡す。LINEへの投稿は運営者が行う。

## 更新パック形式

次のJSONは形式のサンプルです。baseCommitと日付、LINE原稿、出典は実際の確認結果に置き換えます。

~~~json
{
  "baseCommit": "GitHub mainの最新40文字SHA",
  "generatedOn": "2026-10-04",
  "column": null,
  "events": [],
  "line": {
    "announcement": "短い告知文",
    "note": "目的・内容・準備物・参加方法を含むノート",
    "eventDescription": "日時・形式・内容・参加方法を含むイベント説明"
  },
  "sources": ["確認した資料名・URLと、その資料で確認できた事実"],
  "assumptions": [],
  "confirmations": []
}
~~~

- コラムを追加しない場合はcolumnをnullにする。
- 追加する場合はid、title、date、category、excerpt、bodyを持つ記事オブジェクト。bodyはp/h2の配列。本文は正田真澄の一人称、です・ます調、絵文字なし、600〜900字。書き出し「合同会社リバースの正田です。」、締め「共に、次へ。」。
- イベントを変えない場合はeventsを空配列にする。変更する場合は完全なイベントオブジェクトを入れる（部分更新は不可）。id、title、date、type、noteは必須。statusはplanned/completed/postponed/cancelled。
- 日程未定はdateを空文字にし、原稿にも「日程調整中」と書く。確定時は日本時間のYYYY-MM-DDTHH:MM:00+09:00。
- イベントの削除や既存記事の上書きはこの準備機能では行わない。個別に差分を示して承認を得る。
- 「必ず」「絶対」「100％」「誰でも」「確実に」は新規コラムに使わない。
- テーマ・日時・参加方法はJSONとLINE原稿の間で一致させる。ツールは事実や本人の許可を判定できないので確認書で明示する。
- 会員の実名・屋号・具体的数字・合言葉を公開しない。暗号化プロンプト集は指示された場合だけ更新。
- 公開サイトに私的な出典・確認事項・未承認原稿を載せない。GitHubに反映するのはsite相当のJSONだけ。

## 準備画面またはコマンドでまとめて書き出す

tools/update-preparer.htmlを開き、更新パックを貼り付けて「まとめて準備する」を押します。
公開GitHubの最新SHAとデータを読み、古い基準の更新パックは拒否します。
準備画面にGitHubの書き込み権限はなく、確認と書き出しだけを行います。

開発用の代替手段（Node.js 22以上）：

~~~sh
node tools/prepare-update.mjs work/update.json work/review-YYYY-MM-DD-v1
~~~

GitHub mainと作業コピーのHEADの一致を確認し、正本データをGitHubから取得します。
既存の出力先は上書きしません。site/に公開JSON、private/にLINE3原稿・確認書・元の更新パックを分けて出力します。
一時ファイルはwork/内だけに置き、保存用原稿・記録はDrive「おかやまCoAX」に集約してください。

## 連携と承認

GitHub連携に書き込み権限がある場合、ChatGPTは1回の依頼で準備と変更ブランチ・PR作成まで進められます。
mainへの反映と公開には運営者の承認を得ます。承認後の処理は次の「承認します」の依頼で継続できます。
読み取り専用の連携なら準備画面から書き出したJSONを運営者がアップロードします。
トークンや合言葉をチャットに貼る運用にはしません。
